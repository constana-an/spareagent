# 通用任务委托平台：设计（第 2–4 阶段）

状态：**已确认；A–D 已实现（D-75…D-89）**，E–F 待实现。日期 2026-10-19。基线：`feat/macos-app` @ `e810be4`（第 1 阶段已完成：模板撤销级联 D-73、保存反馈 D-74、免开发环境安装包）。

## 0. 目标与边界

小组成员描述需求、上传材料；系统把任务交给在线设备，用设备主人自己的 Codex 执行，返回可下载的交付物。代码审查只是其中一种任务。

**原则：每一类能力先经过真实执行验收再开放。** 平台能表达任何任务，但调度器只派发「已开放」的任务种类；界面明确告诉成员当前哪些任务可以可靠完成。

**不在本轮范围：** 付费、结算、公开市场；对外发送（邮件、发帖）和支付在第一批里**一律不开放**，只生成草稿文件（见第 5 节）。

### 必须先解决的授权问题（阻塞开放，不阻塞开发）

当前唯一的授权记录（`OpenAI support ticket 10766658`）的 `authorization_scope.task_types` 只有 `CODE_REVIEW`，`max_participants = 2`。调度器和数据库触发器都会核对这个范围。因此：

- 翻译、表格分析、修改代码等新种类可以开发、测试，并在 **SIMULATED** 模式下运行；
- 在 **LIVE**（真实消耗订阅额度）下开放任何新种类前，运营者需要确认书面授权覆盖这些用途，并新建（不是改写）一条覆盖新种类的授权记录作为模板。这一点由运营者决定，代码不会自动扩大范围。

## 1. 统一任务模型

每个任务都由同一个结构描述（API 与数据库一致）：

| 字段 | 说明 | 必填 |
|---|---|---|
| `kind` | 任务种类，来自种类目录（第 2 节），如 `TRANSLATE_DOCUMENT` | 是 |
| `requirement` | 需求描述（原 `prompt`），≤ 8000 字 | 是 |
| `attachments[]` | 已上传材料的 ID 列表（第 3 节） | 视种类 |
| `required_capabilities[]` | 由种类推导，成员不用填；可附加（如 `lang:ja`） | 自动 |
| `deliverable` | `{format, filename}`，如 `{"format":"docx","filename":"译文.docx"}`；默认值来自种类 | 自动 |
| `limits` | `{max_duration_seconds, max_output_bytes}`，不超过小组和设备上限 | 自动 |
| `repository` | `{url, commit_sha}` | 仅代码种类 |

**数据库（迁移 0011）：**

- `tasks.repository_url`、`tasks.commit_sha` 改为可空，加 CHECK：代码种类必须有，其他种类必须为空。
- `tasks.kind_version`、`tasks.spec jsonb`（deliverable、limits、附加能力）。`task_type` 列沿用，存 `kind`，旧值 `CODE_REVIEW` 等不变，旧数据无需迁移。
- 新表 `task_inputs(task_id, artifact_id, role, position)`：附件与任务的关联，任务创建后不可改。
- 新表 `task_kinds(kind, version, status, opened_at, acceptance_report_id)`：种类开放状态（第 6 节），只有运营者可改，带审计。

**API：** `POST /v1/experimental-tasks` 接受新结构；旧请求（带 `repository_url`/`commit_sha`、`task_type`）按 `CODE_REVIEW` 等旧种类兼容解析。OpenAPI 升 `1.3.0`。

## 2. 首批任务种类

首批只做三类 + 现有代码审查，每类都有真实可下载的交付物：

| 种类 | 输入 | 交付物 | 设备所需能力 | 结构校验（平台侧，不调用模型） |
|---|---|---|---|---|
| `TRANSLATE_DOCUMENT` 翻译文档 | 1 个 `.docx`/`.md`/`.txt`（≤ 20 MB）+ 目标语言（PDF 暂不支持，见 D-80） | 译文（`.docx`/`.md`/`.txt`）+ 摘要 | `doc` | 输出存在、格式可解析、段落数与原文差异 ≤ 20 %、目标语言字符占比达标 |
| `ANALYZE_SPREADSHEET` 分析表格 | 1–5 个 `.csv`/`.xlsx`（合计 ≤ 20 MB）+ 问题 | `report.md`（含结论与计算过程）+ `charts/*.png` + `cleaned.xlsx`（可选） | `python-data` | 报告存在且引用了输入文件；图片可解码；表格可打开 |
| `CODE_CHANGE` 修改代码 | 仓库 URL + commit + 需求 | `changes.patch` + `summary.md` + 测试输出 | `git`、`code` | 补丁可在固定 commit 上 `git apply --check`；已有的独立校验器（W3）在沙箱中复跑测试 |
| `CODE_REVIEW` 代码审查（已有） | 仓库 URL + commit | `review.md` | `git`、`code` | 现有逻辑 |

后续批次（同一框架，逐类验收后开放）：写作润色、总结、邮件草稿、文档问答、多文件归纳、调研（需要联网能力，单独评估）、文件批量转换、运行脚本、生成文档。

**种类目录** 在代码里（`services/tasks/kinds.py`）定义每类的：输入规则、默认交付物、所需能力、设备端执行配方（第 4 节）、平台结构校验器、中文名称与说明。界面和调度器都只读这个目录。

## 3. 附件

- `POST /v1/experimental-uploads`（multipart，成员会话鉴权）→ 返回 `upload_id`。复用现有内容寻址存储 `LocalArtifactStore`（SHA-256、防路径穿越）。
- 限制：单文件 ≤ 20 MB、每任务 ≤ 5 个、合计 ≤ 30 MB；按扩展名 + 文件头双重检查的白名单；不接受可执行文件、压缩包嵌套、宏文档（`.docm`/`.xlsm`）。
- 上传 24 小时内未关联任务即删除；任务结束 30 天后随任务清理（可配置）。
- 设备取附件：租约里给出 `input_id` 列表，Worker 用节点凭据调用 `GET /v1/leases/{lease_id}/inputs/{input_id}` 下载并核对 SHA-256。只有持有该租约的设备能取，租约结束即失效。
- 隐私：附件存放在运营者服务器上；成员提交前看到「材料会发给小组主人的电脑处理」的提示。

## 4. 设备端执行

每个任务在设备上一个独立的临时工作目录中执行：

```
<临时目录>/task-<id>/
  in/      附件（只读拷贝）
  repo/    仅代码种类：固定 commit 的克隆
  out/     交付物必须写在这里
```

- Codex 以 `workspace-write` 沙箱运行，可写范围只有该工作目录；**网络关闭**（调研类以后单独评估）。
- 执行配方 = 种类目录里的固定提示模板 + 成员需求（作为数据嵌入，不作为指令拼接）+ 交付物要求。
- 结束后 Worker 只收集 `out/` 中符合交付格式、在大小上限内的文件；超出部分丢弃并记录。所有文本经 `redact()` 后上传。工作目录随后删除。
- 表格分析需要 Python 数据库：设备主人勾选「数据处理」能力时，Worker 下载固定版本的工具环境（pandas、openpyxl、matplotlib，按 CPU 固定版本与校验和，方式同 `runtime-pins.json`），只供该能力使用。
- 文档格式：`.docx` 的读写同样放在工具环境（python-docx）中；PDF 只读文本。

## 5. 设备能力与自动接单（第 3 阶段）

**能力声明：** Worker 注册/心跳时上报 `capabilities`：

```json
{"kinds": ["TRANSLATE_DOCUMENT", "ANALYZE_SPREADSHEET", "CODE_CHANGE", "CODE_REVIEW"],
 "tools": {"git": true, "python-data": "2026.10-1", "doc": "2026.10-1"},
 "os": "macos-15-arm64", "codex": "0.163.0"}
```

能力由 Worker 实测得出（例如 `git_available()`、工具环境校验通过），不靠用户勾选声称。

**提供者可调（控制页 + 服务端强制，均有上下限）：**

| 设置 | 范围 | 默认 |
|---|---|---|
| 小组人数 | 2 … min(运营者上限, 授权人数) | 授权上限 |
| 并发任务数 | 1 … 3 | 1 |
| 每 24 小时任务数 | 1 … 50 | 5 |
| 单任务最长时间 | 1 … 60 分钟 | 10 分钟 |
| 允许的任务种类 | 已开放种类 ∩ 设备能力 | 全部已开放且设备具备的 |
| 允许使用的工具 | git / 数据处理 / 文档 | 设备具备的 |
| 允许访问的本机目录 | 默认 **无**（只用临时工作目录） | 无 |

「允许访问的本机目录」只用于以后「文件与工具操作」类任务；首批任务不需要，默认关闭，开启时逐个目录添加，只读。

**调度规则：** 任务的 `kind` 已开放 ∧ `required_capabilities ⊆ 设备能力 ∩ 主人允许` ∧ 限额未满 ∧ 授权范围覆盖该种类 ∧ 主人在线且未暂停 → 自动批准（沿用 D-69 常设批准）并派发。不满足时任务留在队列，并给成员一个具体原因（第 6 节）。

**需要额外授权的动作：** 首批任务的沙箱无网络、只写临时目录，不可能对外发送或支付。以后若有种类需要（如「发送邮件」），流程为：任务先产出草稿 → 成员在网页确认 → 主人单独批准该动作 → 才执行；常设批准**不**覆盖这类动作。

## 6. 完整任务体验（第 4 阶段）

**成员看到的状态（中文）：**

| 状态 | 说明 |
|---|---|
| 排队中（第 N 位） | 有合适的设备，正在等待空位 |
| 等待设备 | 当前没有在线设备具备所需能力，附具体原因（如「小组主人已下线」「该设备未开启数据处理」） |
| 执行中 xx % | 设备上报的进度和阶段 |
| 校验中 | 平台检查交付物 |
| 已完成 | 交付物下载链接 |
| 失败 | 中文原因 + 建议（见下） |
| 已取消 | 成员或主人取消 |

成员可随时取消；执行中的取消会通知设备停止 Codex 并清理工作目录。

**失败原因分类**（每类有中文说明与建议）：输入不合格、超时、超出输出上限、设备中断、交付物未通过校验、授权或限额变化、Codex 登录失效、模型拒绝执行。

**断网与下线：**

- 设备在租约有效期内断网：租约到期后任务回到队列。**尚未开始执行**的任务自动重新分配；**已开始**的任务按种类决定：无副作用的种类（首批全部）最多重试 1 次，可分配给其他设备；`max_attempts` 记录在任务上。
- 主人点「下线」：控制页先问「正在运行的任务怎么处理」——「运行完再下线」（等待最多单任务上限）或「立即停止并交还队列」。暂停期间不接新任务，排队任务转给其他在线设备或继续等待。

**提供者看到的：** 正在运行的任务（种类、成员、已用时间、进度）、过去 24 小时任务数/上限、累计执行分钟、每个成员的使用量；暂停后对已有任务的处理方式。

## 7. 能力开放流程（验收门槛）

`task_kinds.status`：`DEVELOPING` → `SIMULATED_OK`（模拟执行全流程通过）→ `LIVE_ACCEPTED`（真实设备执行验收通过，附报告）→ `OPEN`（运营者开放）。

- 只有 `OPEN` 的种类出现在成员的提交界面，并可被调度。
- `LIVE_ACCEPTED` 需要：至少 3 个真实样例（含 1 个边界样例）在一台全新安装的设备上执行成功、交付物通过结构校验并经人工检查，报告存入 `reports/`。
- 运营者可随时把种类改回非开放，已排队的该种类任务转为「等待设备」并说明原因。

## 8. 下一轮验收脚本（对应你给的目标）

1. 一台没有开发环境的 Mac 下载 `SpareAgent-mac.zip` → 打开 → 登录 → 点「上线」→ 得到邀请码。
2. 另一人用邀请链接加入，分别提交：翻译一份 `.docx`、分析一份 `.xlsx`、修改一个固定 commit 的代码仓库。
3. 三个任务全部自动批准、自动执行，成员下载到：译文 `.docx`、`report.md` + 图表、`changes.patch` + 测试输出。
4. 提供者把「每 24 小时任务数」调到当前已用数 → 第 4 个任务显示「等待：已达今日上限」；调高后自动继续。
5. 提供者点「下线」→ 新任务显示「等待设备：小组主人已下线」；运行中任务按所选方式处理。
6. 断开设备网络 1 次 → 任务按第 6 节规则恢复或重新分配。

步骤 2–3 的 LIVE 部分需要第 0 节的授权确认；在此之前用 SIMULATED 完成同一脚本。

## 10. 已知风险与待定事项

1. **授权范围**（第 0 节）：新种类的 LIVE 开放取决于运营者的书面授权。
2. **macOS 首次打开**：安装包未签名，新版 macOS 要到「隐私与安全性」点「仍要打开」。彻底去掉这一步需要 Apple 开发者账号签名并公证的安装器。
3. **服务器地址会变**：安装包内写的是局域网 IP（当前 `10.0.0.16`）。换网络后包失效，需要固定域名或 Tailscale 私有地址，再重新打包。
4. **附件隐私**：材料经过运营者服务器并在主人电脑上处理；需要在加入和提交时清楚告知。
5. **结构校验不等于质量保证**：平台只能检查格式和完整性，译文质量、分析结论仍需成员判断；界面标注「未经人工核对」。
