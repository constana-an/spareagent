# Week 6 security review and pilot limits

Reviewed on 2026-10-18 against Week 5 merged `main` plus this change. This is a private,
trusted-friends experiment; no public deployment, signup, payments, resale, pooled
credentials, paid routes or participant expansion is introduced. LIVE is default-off.
The owner-supplied Support ticket 10766658 is project-specific correspondence requiring
operator validation, not independently authenticated vendor endorsement.

| Boundary | Evidence / change | Remaining limit and safe operating rule |
|---|---|---|
| Coordinator identity | Existing node-scoped short-lived access tokens, hashed refresh/enrollment secrets, parent revocation, path/lease ownership; HTTPS required remotely. URL now rejects embedded credentials, query/fragment/path; node client ignores inherited proxy/netrc configuration and redirects. | Trust the operator's HTTPS host and CA. A compromised coordinator can submit untrusted prompts; Alice must inspect each one. No certificate verification bypass. |
| Browser access | Existing invitation-only one-time login, opaque hashed sessions, HttpOnly/SameSite Strict/Secure, Origin checks, role/participant scope; new metrics require active group membership; report owner/requester only; relay GET-only allowlist for both. | Group aggregate task/device counts are visible to active members. Prompts/artifacts remain participant-scoped. No public signup or anonymous access. |
| ChatGPT credentials | Official CLI login-status classification only, allowlisted child environment, forced ChatGPT route, own-device login; wheel includes no server settings. Local node state now rejects group/world-readable files and symlinks, writes via private random temporary file + atomic replacement. | SpareAgent does not inspect auth.json/Keychain. CLI installation source and host trust require owner validation. Version output alone cannot prove publisher identity. |
| Subscription funding | Existing no-extra-Credits attestation, no paid fallback, limit cooldown; preflight labels owner statements and requires a fresh manual balance check. No API/token-sharing integration added. | Upstream can spend existing extra Credits. Software cannot guarantee source; stop unless purchased AND granted balances are zero and reload is off; manually inspect usage afterward. Token counts/zero SpareAgent metering are not receipts. |
| Prompt injection / escape | Existing named OS sandbox: checkout-only/minimal reads, review read-only, no tool network/escalation, user config/rules ignored, MCP/apps/search/subagents disabled. No-inference actual OS probe passes on this Mac; deterministic injection regression checks immutable argv/permissions. Shared oversized/NUL prompts now rejected on the device too. | A preamble does not establish model resistance. OS/CLI vulnerabilities and model persuasion remain risks; only public pinned repositories, no private files, mandatory approval. Repeat isolation probe on each device/version. No hostile multi-tenant guarantee. |
| Public repository checkout | Existing anonymous HTTPS GitHub-only full SHA checkout, empty Git HOME, disabled helpers/hooks/redirects/submodules/LFS, tree/path/file/size/time limits. Same implementation moved to shared stdlib package, backend compatibility exports retained. | Checkout can contact public GitHub; model tool networking stays off. Initial pilot is CODE_REVIEW only. Do not run arbitrary repository tests on the owner's host. |
| Consent / authorization expiry | Existing separate join/sharing/individual approval, pause/revoke/kill switch, accept recheck. New current sharing-terms check and recheck of durable authority on progress/renew/complete and verifier finalization. Expiry/withdrawal cancels and withholds worker artifacts; cancelled verification reports no longer present a successful pass. | Pause governs new work; revoke cancels existing work. At most five seconds between renew attempts plus transport delay; disconnected devices cannot receive an immediate remote kill. Use local stop when needed. |
| Lease / retry / restart | Persisted attempts, bounded leases, same-key idempotent completion and atomic usage; server restart reuses records. New local cancellation for node-auth/ownership rejection and lease-window expiry even on server HTTP errors. Late LIVE success after task deadline becomes timeout. | A process can spend some usage before observing disconnect/cancel. No automatic real-subscription retry, account switching or limit exhaustion drill. |
| Results / verification | Independent verifier and DB publish guard retained. Recheck authority before publication; cancelled/stale workers cannot publish. UI separates execution from VERIFIED/UNVERIFIED/FAILED/CANCELLED and exports redacted evidence. | VERIFIED means supported trusted checks only. Reviews/unsupported recipes stay UNVERIFIED. Reported tokens/device identity can be forged by a malicious owner; a protocol report never establishes physical execution or billing. |
| Installation / supply chain | Separate worker-only wheel (httpx direct dependency), reviewed script + explicit SHA, isolated user venv; no curl-pipe-shell, sudo, backend install, automatic login, registration, background launch or LIVE. Fresh-wheel tests on macOS/Linux; actual Mac installer test uses a harmless fake CLI sentinel. | Operator must distribute reviewed bytes/checksum privately. Python/Git/Codex and dependency registries remain trusted. httpx transitive dependencies are resolved at install time; wheel/CI artifact is not a signed upstream release. |
| Prompt/result privacy | Existing secret redaction, bounded streams/artifacts, participant-only events/download; new report omits prompts, results, credentials and home paths. QA secrets stay in temporary private files. | Regex redaction is not DLP; do not submit secrets. Operator DB/backups/artifacts contain task data and need restricted storage/retention; the app does not claim encryption-at-rest or automated deletion. Delete private pilot evidence according to participant agreement. |

Unsafe conditions are blocked: missing/expired/uncovered authorization, unauthorized members,
wrong/unknown CLI login, additional Credits consent failure, revoked device, unsupported
CLI/sandbox, remote HTTP, missing current terms, missing individual approval or an expired
lease. A readiness report is not execution authorization and never changes any of these.

The two-device real experiment, real cancellation/timeout and naturally reached real
usage limits remain manual. Do not describe fake CLI, protocol, container, OS-marker or
browser-simulation results as real subscription evidence.
