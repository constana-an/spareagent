## 分工与设备

| 编号 | 角色 | 本次职责 |

建议预留 **60–90 分钟**，不含首次安装、Tailscale 配置或授权资料补齐时间。

## 本次范围与用量上限

- 第一部分为无模型检查；未通过时不得进入真实任务。
- 第二部分仅规划 **1 笔跨用户 CODE_REVIEW，执行上限 600 秒，并发 1，无自动重试**。
- 若 2 号缺少适用于本人、当前设备及配置的成功 owner check，需先单独明确选择一次
  `codex-check`，并人工核对其用量。这是额外一次可能消耗额度的检查，不包含在默认任务内。
- 不复用别人的检查结果，不把 `--skip-inference`、fake CLI 或模拟任务当作真实验证。
- 不测试账号切换、额度耗尽、API key、额外购买/赠送 Credits、自动充值或付费回退。
- 断网、重启、运行中取消和超时演练留到首轮结束后，另行决定，不自动追加真实任务。

## A．准备主服务与网络（约 15 分钟，无推理）

1. 1 号确认本轮使用的代码/镜像版本及本机私有 Compose 目录。最近记录为所有容器已停止；
   这只是上次状态，执行当天重新检查。只恢复 `spareagent-pilot`，不启动旧开发环境或 Week 4 库。
2. 先检查现有数据卷和备份，不覆盖唯一备份；开始前生成带时间戳的新数据库备份，保存在
   受控私有目录。检查容器 `HostConfig.AutoRemove=false`，不要使用退出自动删除容器存储试验数据。
3. 人工确认 API、Scheduler、Verifier 的 `EXPERIMENT_LIVE_ENABLED=false`，生产身份验证开启、
   开发身份头关闭，再启动主服务；检查 API `/readyz`、Dashboard、Scheduler 和 Verifier。
4. 默认先用 CMU-SECURE 的 LAN HTTPS。确认实际 IP、证书、浏览器 Origin 和 Worker API URL 一致，
   不沿用可能变化的旧 IP，也不跳过证书校验。
5. 由 2 号、3 号分别从自己的设备访问 Dashboard；2 号同时检查 API `/readyz`。
   在实际使用的网络上检查，1 号本机访问通过不能代替用户设备通过。
6. 若校园网无法互访，暂停后切换 Tailscale：先配置私有 Serve、访问规则、新 HTTPS 地址和
   应用 Origin，再重新做两台用户设备检查。当前未配置 SpareAgent 的 Tailscale 入口；
   安装 Tailscale 或把 URL 改成 `100.x` 不能直接通过本步骤。不启用公开 Funnel。

**通过标准：** 两位用户均能通过有效 HTTPS 到达正确服务；生产认证有效；LIVE 仍关闭。
网络或证书未通过就停在此处，不边跑真实任务边排查网络。

## B．安装、邀请及授权（约 20 分钟，无推理）

1. 2 号核对操作员提供的 Worker wheel SHA-256，安装官方 Codex CLI 与 Worker，使用本人登录。
   Python 3.12+、Git 为运行前提；2 号、3 号均不安装后端、数据库或 Docker。
2. 1 号创建正式的两人组，分别给 2 号、3 号发送各自的一次性邀请；过期后重新签发，
   不发管理员登录码。两人分别登录并自行阅读、接受条款，不代勾选。
3. 组限制为两位参与者、CODE_REVIEW、并发 1、每日 3 笔、任务 600 秒；本次任务预算仍仅 1 笔。
4. 1 号本人审阅项目已有的供应方对应资料，确认技术路线、非商业范围、参与者上限及有效期，
   然后按原运行手册记录和核验授权。仅有 ticket 编号不表示核验通过，不能自动延长授权。
5. 2 号通过自己的 Dashboard 生成一次性节点登记 token，在自己的 Mac 登记 Worker；
   token 不放进 shell 历史，私有 CA 使用 `--ca-file`，不复制其他设备的 `node.json`。
6. 2 号连接本人的订阅设备，选择正式组、逐任务批准及上述限制，自行完成分享同意。
   服务端 LIVE 保持关闭。
7. 2 号运行 `spareagent-worker pilot-check`。保存脱敏报告并逐项检查；LIVE 关闭造成的
   `LIVE_EXECUTION_DISABLED` 属于预期。报告中的人工项目仍需本人确认，不能以退出码代替验收。

**通过标准：** 两个独立参与账号、两台真实用户设备、正确归属的 Worker、有效授权、本人同意
均能核对；1 号、3 号不接收 2 号的 ChatGPT 登录文件、cookie、OAuth token 或 API key。

## C．真实执行前的最后检查（约 10 分钟）

由 2 号当场确认并记录检查时间：

- [ ] 没有额外购买或赠送 Credits；自动充值已关闭；余额/状态不明确时停止。
- [ ] 当前 owner check 可适用于本人及这台设备；若缺失，先单独决定是否执行额外检查，
  并在完成后核对用量。未通过时不进入跨用户执行。
- [ ] 当前授权、组、分享设置、任务限制和本机权限隔离均满足原运行手册。
- [ ] 两人同意本次只运行一笔任务，不自动重试；任何一人都可以叫停。

这部分包含真实执行许可，不由安装脚本、`pilot-check` 或本计划自动确认。

## D．一笔跨用户任务（约 10 分钟，手动开启）

1. 2 号明确选择启动前台 Worker。1 号确认有效授权与全部前置条件后，才手动开启组分享
   和 API、Scheduler、Verifier 的 LIVE 开关，并记录开启时间。重新检查就绪状态。
2. 3 号选择 **2 号的设备**，明确选择 LIVE，只提交一次：

   ```text
   task_type: CODE_REVIEW
   repository_url: https://github.com/octocat/Hello-World
   commit_sha: 7fd1a60b01f91b314f59955a4e4d4e80d8edf11d
   max_duration_seconds: 600
   prompt: Review the pinned public repository read-only. Summarize its contents and
           any concrete issues. Do not change files, read private paths, or use network tools.
   ```

3. 先不批准，观察约 10 秒：任务应保持等待批准，不开始执行；若已经运行，立即停止并记录缺陷。
4. 2 号核对请求人、设备、完整提示词、仓库、SHA 及超时均与计划一致，再本人批准这一笔任务。
   提交后 **10 分钟内须完成批准并由 Worker 接单**；批准不会重置等待期限。
   实际执行仍为 **接单起最多 600 秒**。已超时任务不恢复，不自动重试或批准新任务。
   需要时使用 `pilot-check --task-id TASK_ID` 核对，报告不代替人工批准。
5. 两人观察任务时间线和 2 号本机 Worker，记录 task/attempt ID、批准、开始和结束时间。
   出错、限流或认证失败不自动重试，也不换账号继续跑。
6. 3 号能重新打开任务，看到结果和平台验证报告。纯 CODE_REVIEW 的预期是执行可
   `SUCCEEDED`，验证标注 **UNVERIFIED**；不得因此宣称审查语义正确或强制改成 VERIFIED。

1. 2 号立即在官方用量页面人工核对：是否仅使用订阅包含额度、额外 Credits 未变化。
   若页面尚不能确认则记为待确认，不根据 token 数、零计费字段或任务成功推断资金来源。

   |---|---|

   | 两台用户设备由本人确认及实际网络方案 | |
   | 代码/镜像、Worker、Codex CLI 版本与认证类型 | |
   | 授权引用、同意及逐任务批准的审计引用 | |
   | task ID、attempt ID、开始/结束时间、耗时 | |

3. 1 号关闭所有相关进程的 LIVE 开关。2 号暂停或撤销分享，并停止前台 Worker。
   确认无运行任务且不会开始新任务，再保存最终数据库备份。
4. 需要继续停机时，先核对 AutoRemove 和卷挂载，再停止本次主服务并确认数据卷仍在；
   不运行 `down -v`、`make clean` 或 volume prune。

## 立即停止条件

出现证书/身份不符、缺少有效授权或本人同意、未经批准开始执行、异常读取私人内容、
API key/额外 Credits/自动充值、资金来源不明、限流或认证失败、意外多任务/重试时停止。

运行中需要立即停止本机执行时，由 2 号使用 `spareagent-worker stop` 或 Ctrl-C；
Pause 只阻止新任务，不保证终止已有任务。1 号同时取消任务并关闭 LIVE。
断网时不能假设远程按钮立即到达设备，须由 2 号本机停止。保留脱敏日志，不为了证明成功而重跑。
