# 用户体验修正（第 1–5 项）

本次改动基于 `98000fe`（App 0.17.5，build 25）。

1. 额度无法读取时显示“额度未知”，保留上次成功读取时间；近期明确发生额度耗尽时仍提示已用完。主人控制页与 Mac 菜单栏使用同一判断。
2. 新任务表单显示后再滚动并聚焦需求输入框，“改一改再提交”也使用该流程。
3. 失败页区分修改输入、检查后重试、需要主人处理的情况，提供日志入口；错误代码和原始摘要收进“技术详情”。点击重试入口只恢复草稿，仍需用户检查并提交。
4. 主人与成员看到一致的试运行说明，提交按钮显示本次是“提交真实任务”还是“开始试运行”。更改高级选项后，说明与按钮同步更新。
5. 普通首页默认展示小组邀请码加入，主人／运营者登录入口保留。成员可填写最多 40 字的昵称；主人端按“本机备注 → 成员昵称 → 成员编号”的顺序显示。昵称由成员自填，不代表身份认证。

发布服务端前，需要备份数据库并运行项目现有迁移流程，应用 `0019_member_nicknames`。该迁移只新增可空的昵称列，不改动现有成员身份、限额和记录。旧版客户端可以省略昵称；重新加入时省略昵称会保留已有值。新版网页需要配套服务端才能提交昵称。

本次没有增加基于结果的连续对话，也没有修改真实执行的授权、接单或额度消耗规则。
