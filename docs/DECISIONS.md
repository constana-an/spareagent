# Decisions and deviations (Week 1)

Where the specs were silent or contradictory, the more restrictive security interpretation
was chosen. Every deviation from `contracts/openapi.yaml` / `db/migrations/0001_initial.sql`
is listed here.

| ID | Decision | Why |
|---|---|---|
| D-01 | **Contract defect fixed.** `/v1/leases/{lease_id}/complete` response was `{description: finalized, idempotent replay permitted}`; the unquoted comma in a YAML flow mapping creates an extra key, so the shipped spec failed OpenAPI 3.1 validation. Now `{description: 'finalized; idempotent replay permitted'}`. | Spec must parse with a standards-aware validator (ACCEPTANCE gate). |
| D-02 | `Task.result_summary` is derived from the payload of the task's terminal event (`task.succeeded/failed/cancelled/timed_out`). No schema column was added. | Avoids a schema change in W1; events are the durable audit trail anyway. |
| D-03 | Another user's task/artifact, and malformed UUIDs, return **404** (never 403). | No existence oracle (ACCEPTANCE allows 404 or 403). |
| D-04 | Worker control-plane HTTP endpoints (`/v1/workers/*`, `/v1/leases/*`) exist with the contracted operationIds but **always return 403 `NODE_AUTH_UNAVAILABLE`** in W1. The local mock worker calls the same `LeaseService` in-process. | Node credentials are W2. Accepting dev/consumer auth there would let a user act as a worker ("worker claims must not self-elevate"). |
| D-05 | Cancelling a `RESERVED` task goes straight to `CANCELLED` (attempt marked `CANCELLED`, capacity released). `CANCELLING` has no event type in `events.schema.json`, so it is emitted as `task.progress` with `payload.status = "CANCELLING"`. | Attempt never started; event types are fixed by the contract. |
| D-06 | **Extension:** `POST /v1/admin/resources/{id}/approve` (ADMIN role only, audited, `PERSONAL_SUBSCRIPTION` always refused with 422 `POLICY_VIOLATION`). Added to `contracts/openapi.yaml` with `x-spareagent-extension`. | AUTH-002 requires a trusted path for eligibility that providers cannot use. |
| D-07 | **Extension:** `GET /v1/tasks/{id}/artifacts/{artifact_id}/content` (owner only, `Content-Disposition: attachment`, `nosniff`, `X-Artifact-SHA256`). Added to the contract. | "Inspectable artifact" in the Definition of Done; descriptor list alone cannot be inspected. |
| D-08 | Added transitions `QUEUED -> FAILED` (budget cannot cover next attempt, or attempts exhausted), `QUEUED/RESERVED/RETRY_PENDING -> TIMED_OUT` (task deadline = `created_at + max_duration_seconds`), `RESERVED -> FAILED` (lease expiry exhausting `max_attempts`). Insufficient budget fails fast with reason `BUDGET_INSUFFICIENT` instead of waiting forever; **no attempt is created**. | PRD lists terminals but not every edge; never start an attempt without headroom. |
| D-09 | Dev auth "bound to localhost": the API port is published on `127.0.0.1` only, **and** the app accepts `X-Dev-User-ID` only if the client IP is in `DEV_AUTH_TRUSTED_CIDRS` **and** the `Host` header is `localhost`/`127.0.0.1`/`[::1]`. Compose trusts Docker bridge ranges because Docker's port proxy forwards from the bridge gateway. Default (outside compose) is loopback only. | Defence in depth + DNS-rebinding protection; `DEV_AUTH_ONLY` defaults to **false** and is refused at startup unless `APP_ENV=local`. |
| D-10 | Gateway: unknown body fields -> 422 `UNSUPPORTED_PARAMETER`; `stream:true` -> 422 `UNSUPPORTED_STREAMING` (wins over other errors); unknown/unroutable alias -> 404 `MODEL_NOT_FOUND` (404 added to the contract). Aliases are bound to a registry resource and are listed/routable only while it passes `ResourceEligibilityPolicy`. Mock usage is stored with `estimated_cost_cents = 0` and the response carries `X-SpareAgent-Billable: false` (the body shape is fixed by the contract). | Explicit capability errors (G4); never route personal resources. |
| D-11 | `Idempotency-Key` charset restricted to `[A-Za-z0-9._:-]{8,128}`; missing/invalid -> 400. Body digest = SHA-256 of canonical JSON of the *validated* body (commit SHA lower-cased). | Contract lists 400 for createTask; canonicalisation makes replays robust. |
| D-12 | `repository_url` must be exactly `https://github.com/<owner>/<repo>` (no userinfo, port, query, fragment, `..`, extra path). Prompt: 1..12000 chars, not blank, no NUL. Integers are strict (no floats/strings/bools). | Contract pattern `^https://github\.com/` alone would accept `https://github.com.evil...`-style prefixes in looser validators and arbitrary paths. |
| D-13 | Migration runner (not Alembic): each file runs in one transaction together with its `schema_migrations` row; the file's own top-level `BEGIN;/COMMIT;` lines are stripped; a SHA-256 checksum makes shipped migrations immutable; `*_seed_*` files are excluded from `make migrate` and applied by `make seed-dev` (local only, repeatable). | WEEK1 Day 2 item 1; one system only. |
| D-14 | `ExecutionRequest` gained `attempt_number` and `task_type` fields. | Lets the deterministic mock vary per attempt (transient-fault injection). |
| D-15 | Consumer-visible event payloads never include `lease_id` or `worker_id`. | Lease ids are worker capabilities. |
| D-16 | Invalid `Last-Event-ID` -> 400 `INVALID_LAST_EVENT_ID`. The SSE stream ends after the terminal event is delivered; while open it polls committed events every 0.5 s and sends `: keepalive` comments every 15 s. | Replay never skips committed events because seq is allocated under the task row lock. |
| D-17 | Gateway rate limiting (per user, per minute, Redis) **fails open** if Redis is unavailable. | W1 best-effort; documented as a known limitation, to be hardened with gateway budgets in W5. |
| D-18 | Only `PROVIDER_MODE=mock` is accepted; any other value fails startup. The optional OpenAI adapter (Day 5 stretch) was **not** implemented. | No credentials or spend in W1. |
| D-19 | Tests run in a compose `test` container against an isolated database `spareagent_test` (dropped/recreated per session) and Redis DB 15. Postgres/Redis are also published on `127.0.0.1:55432` / `127.0.0.1:56379` for host tooling. | "Dedicated isolated database"; avoids clashing with a local Postgres on 5432. |

## Week 2 (remote worker network)

| ID | Decision | Why |
|---|---|---|
| D-20 | **Three credential types**, all random 256-bit bearer secrets stored only as `HMAC-SHA256(NODE_TOKEN_PEPPER, secret)`: single-use **enrollment token** `sa_enr_` (TTL ≤ 7 d), long-lived **node key** `sa_nk_` (30 d, exchange-only), short-lived **access token** `sa_at_` (15 min, every node call). Access tokens die with their parent node key, so rotation/revocation is immediate (checked against the DB on every request). | Short-lived, node-scoped, revocable, no raw secrets at rest. HMAC (not bcrypt) is appropriate for high-entropy random secrets and allows indexed lookup. |
| D-21 | Registration requires an enrollment token issued by an **ADMIN** (any public-type resource) or by a **PROVIDER for their own admin-APPROVED resource**. Consumer and dev (`X-Dev-User-ID`) auth are never accepted on node endpoints; node tokens are never accepted on consumer endpoints. Unknown/used/expired/revoked enrollment tokens all return the same 401 `ENROLLMENT_INVALID`. | "No anonymous self-registration"; no oracle on token state. |
| D-22 | `PERSONAL_SUBSCRIPTION` resources cannot be enrolled: application check **plus** a DB trigger on `enrollment_tokens` (migration 0003). Week 1 CHECK constraints and per-claim `ResourceEligibilityPolicy` re-checks remain, so even a node row forged for a personal resource receives no work (tested). | Defence in depth for the core policy invariant. |
| D-23 | `worker_nodes.revoked_at` added (0003). Admin revocation revokes every credential, marks the node OFFLINE and forces its active leases to expire immediately, then runs recovery (tasks go to RETRY_PENDING or FAILED within max_attempts). | Revocation must take effect on in-flight work, not only future calls. |
| D-24 | **Pull scheduling.** Remote nodes claim work through a bounded long poll `GET /v1/workers/{id}/leases/next?wait_seconds≤25` that reuses `Dispatcher.dispatch_once(worker_ids=(node,))` — the same `FOR UPDATE SKIP LOCKED` task + worker locking and capacity check as Week 1. The local worker now also claims only for its own nodes (hybrid mode, one lifecycle). An unaccepted reservation is re-delivered to the same node on the next poll, or lapses after one lease window. | Outbound-only workers, atomic capacity reservation, no double claims. Polling (0.5 s DB interval while waiting) instead of Redis pub/sub keeps Redis non-authoritative. |
| D-25 | New central `scheduler` process (`services/scheduler/runner.py`): lease expiry, retry promotion, and **capacity reconciliation** (`active_tasks` recomputed from attempt rows). All idempotent under the existing row locks, safe to run alongside API and workers, and the basis for recovery after API or worker restarts. | Remote-only deployments must recover without the local worker. |
| D-26 | Artifacts are submitted **inline** (base64, ≤ 5 MB total, ≤ 8 items, allow-listed media types and safe names) in `POST /v1/leases/{id}/complete`, not via a separate upload. They are verified and published in the finalization transaction, so a replay or stale completion can never publish twice. | Atomicity over streaming; W1 artifact sizes are tiny. |
| D-27 | **Usage is computed by the API**, never accepted from the node (`usage` fields are rejected with 422). Retryability is decided by the API: a node's `retryable=true` is honoured only for `TRANSIENT_PROVIDER_ERROR` and `WORKER_SHUTDOWN`, and always bounded by `max_attempts`. | A node cannot inflate billing or extend retries. |
| D-28 | Prompts are passed through `redact()` before leaving the API in a lease assignment; consumer identity is never sent (`user_id` is `"redacted"` on the node). | Minimise data exposure to provider nodes. Known-pattern redaction only — see security concerns. |
| D-29 | HTTPS for remote workers: compose runs a second stateless API listener `api-tls` (uvicorn TLS, port 8443) with a throwaway dev CA generated by `scripts/dev_certs.py`; workers verify it with `--ca-file`. The CLI refuses `http://` unless `--allow-insecure-http` **and** the host is loopback. | Real TLS in the demo without a reverse proxy; production should terminate TLS with a real certificate (and consider mTLS, W3+). |
| D-30 | Worker graceful shutdown (SIGTERM / `spareagent-worker stop`): stop polling, give in-flight work `--shutdown-grace` seconds, then hand the lease back with `WORKER_SHUTDOWN` (retryable) and report `OFFLINE`. A hard kill (SIGKILL/network loss) is handled by lease expiry instead. | Fast, explicit hand-back without relying on lease timeouts. |
| D-31 | `NODE_TOKEN_PEPPER` must be ≥ 16 chars and must not be the dev default outside `APP_ENV=local` (startup fails). | Fail closed. |
| D-32 | The seed `0004_seed_dev_week2.sql` adds a dev ADMIN user and a non-eligible PERSONAL_SUBSCRIPTION resource (to demonstrate exclusion). Week 1 tests asserting migration lists / seed counts / the 403 worker stub were updated accordingly (worker endpoints now return 401 for non-node credentials). | Explicitly documented test-expectation changes. |
